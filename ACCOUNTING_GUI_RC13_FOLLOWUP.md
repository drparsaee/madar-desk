# Madar Desk RC13 accounting GUI: evidence-based acceptance follow-up

**Audit date:** 2026-10-22  
**Scope:** Read-only review of the **existing** RC13 smoke log, GUI harness, current React accounting screens, and relevant host/domain test documentation. **No EXE or smoke rerun, new build, Git, real APPDATA, release modification, SQL/Parsian, finance record, or running-app interaction.**

**Legacy TOMAN accounting workspace:** `src/App.jsx:850–859,917–920` gates an `AccountingWorkspace` route on `canManage` (the React `lanStatus.user.role === 'admin'` check is at `src/App.jsx:557`). `src/accounting_workspace.jsx:7–12,227–272,345–365` mounts full-screen tabs and loads via `api.accountingRead(projectId)`; real mutating UI buttons route through `api.accountingCommand(...)` and retry tokens. **Legacy document routes visibly exist, but smoke never clicks them:** `src/accounting_workspace.jsx:323–344,375–405` offers task sales draft, unpriced checklist purchase intake, `intake.price`, `intake.convert`, `document.review` and `document.issue` for sales/purchase; `:273–296,476–530` offers `receipt.record`, `payment.record`, `funds.deposit` via confirmation forms. `:38–52` constrains settlement to outstanding **Issued** documents and safe amounts/dates. 

**Separate RIAL V2 journal:** `src/App.jsx:860–895,919–921` mounts a distinct admin-only, intentionally read-only V2 journal panel with company/period input and **new-empty-ledger activation only**. `src/rial_journal_panel.jsx:4–6,13–24,52–78,110–150` expects canonical **RIAL decimal strings**, validated company/period/schema; the `App.jsx` call sets `canPreview=false`. The legacy currency switch is **not** V2 activation or migration. The current host source is newer than some historical handoffs: `native_app.py:1512–1525` has a **conditional supplier purchase issue** path through `ir_purchase_host_adapter.py` when V2 is activated, plus same-finance-CAS handling. This is a real code-level integration candidate, **not** evidence that the GUI tested it or that all sales, treasury and legacy documents co-post into V2. Historic `IR_V2_INTEGRATION_ACCEPTANCE.md:35–43` predates that specific host path; use the latest source when scoping new tests.

### Gating interpretation

- **Controlled navigation/demo of current RC13:** **PASS supported** for the narrow existing single-user, disposable-profile smoke described above.
- **Legacy accounting financial E2E accepted for beta with synthetic transactions:** **BLOCKED** until **RC13-G01 through G05**, negative cases and real mounted-UI screenshots are completed by a separately authorized owner. The existing Bridge/API synthetic tests are valuable positive evidence but **cannot be re-labelled** as GUI E2E.
- **Cheque or inventory features marketed as available in RC13:** **BLOCKED** by **RC13-G06/G07**; UI currently exposes only generic settlement and non-stock-tracked catalog. Feature names in the old Parsian guide, or standalone pure kernels, are not a mounted native workflow.
- **Legal accounting or live production financial acceptance:** **NOT ESTABLISHED**. Migration of historical Parsian records, verified source currency, local financial law/tax/e-invoicing, secure backup/restore and independent signed audit/reconciliation need separate reviews. This is not a legal-compliance certification.

A PASS requires assertions over both UI **and** authoritative persisted state, not a click or a DOM label.

**No new test file was created by this tranche.** A static contract test asserting the absence of these flows from the old smoke would merely re-prove their absence; it could never replace a real isolated financial GUI run and might encourage another fake green release gate. This is an **evidence audit only**.
