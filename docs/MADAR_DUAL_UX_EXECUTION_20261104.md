### Extended close/recovery safety and gated validation

- New task-saving regression: a failed host write combined with a blocked browser recovery write no longer downloads an unrelated stale recovery key. An in-memory current failed snapshot takes precedence; the Chrome test seeds stale data, captures the exported JSON, verifies that the failed card is present and the old stale card is absent, then confirms a successful explicit server refresh invalidates the old recovery key. Explicit recovery/restore paths clear the failed snapshot only after the authoritative reload succeeds, not before a failed reload.
- `window.__madarAccountingConfirmNativeClose` exposes a read-only, fail-closed unsaved-editor decision for the **native titlebar X**, not only in-app ribbon/sidebar exit. `NativeAccountingCloseGate` vetoes the first pywebview closing event; a separate worker evaluates the browser decision to avoid blocking-event `evaluate_js` deadlock. An unknown/unloaded JS state denies exit. Final accounting backup is verified **before** invoking `window.destroy()` so it does not depend on a second closing event. One-shot approval is invalidated if destroy is not observed or raises, and a live desk can be unlocked for a future retry. Confirmed company-switch requests retain their existing mandatory-backup path.
- Native synthetic gate tests use fake windows with accepted/rejected decisions, missing callbacks, backup failure, duplicate close attempts, no second closing event and destroy-after-event failure. Existing synthetic desktop exit and company-switch lifecycle tests were updated for the first-close veto and deferred decision contract; the original mandatory backup and distinct company-book assertions are preserved. This is **not** proof that real Windows WebView2 dispatches close events with the same timing or thread affinity. Native acceptance on a disposable binary/profile, including injected failing backup, remains release-blocking.
- In-flight financial mutations now mark the invoice/purchase form `inert`, with row/ID inputs disabled and state mutation handlers checking the locked/pending state; this prevents user edits while an awaited approved-document `reopen` may replace editor state. UXFocus Chrome verifies the native dirty-form veto in its synthetic React environment. A real successful `reopen` command and journal/GL postconditions remain outside this browser fixture, which rejects mutation commands by design.
