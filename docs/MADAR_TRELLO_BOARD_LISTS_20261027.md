# تصمیم و شواهد برد فشرده / عملیات لیست مدار | 2026-10-27

## درخواست و تصمیم

- تنظیمات هر مرحله داخل منوی سه‌نقطهٔ همان ستون باشد، با تغییر نام، توضیح، رنگ، جابه‌جایی و افزودن کارت. تنظیمات عمومی در برد اختصاصی صرفاً مسیر بازیابی آرشیو را نگه می‌دارد.
- ستون‌ها عرض ثابت `288px` و ارتفاع طبیعی داشته باشند؛ ستون بلند اسکرول عمودی داخلی، برد اسکرول افقی و ستون خالی ارتفاع کوتاه داشته باشد.
- «افزودن یک لیست دیگر» در انتهای برد، فرم کوتاه درجا با تأیید/انصراف، RTL و پشتیبانی تم روشن/تاریک داشته باشد.
- در حذف، آرشیو و جابه‌جایی مرحله، Floating Labelهای orphan یا دارای مختصات قدیمی روی ورودی‌های دیگر باقی نمانند؛ native label حفظ شود.
- دادهٔ مالی/کارت‌ها در عملیات ستون از بین نروند. در برد اختصاصی از **بایگانی قابل بازیابی** استفاده می‌شود، نه حذف دائمی.

## شواهد آزمون این نوبت

- اجرای `node --test tests/*.test.cjs`: **۴۵۰ تست پاس، صفر شکست**.
- اجرای `npm run build`: **موفق**؛ تولید Build معادل ساخت/نصب EXE نیست.
- آزمون WebView2 با `MADAR_QA_VIEW=board-list-menu` در پروفایل مجزا: پنج lane هرکدام عرض ۲۸۸px، ارتفاع‌های متفاوت ۱۵۴ تا ۳۷۱px، اسکرول افقی برد و popup در viewport؛ گزارش اجرای قبلی.
- آزمون WebView2 با `MADAR_QA_VIEW=board-add-create`: شش ستون پس از ایجاد `QA list creation`، فرم بسته، گزارش بدون خطای JS. فایل JSON ایزوله شش stage، دو board و چهار task دارد؛ هر دو برد فعال stage جدید را حفظ کرده‌اند.
- اجرای مستقیم `data_model.validate_plus` روی فایل JSON **ایزوله** پس از افزودن ستون: **PASS**. این آزمون فقط قرارداد ساختار و referenceهای JSON را می‌سنجد و کنترل host-side ACL را ثابت نمی‌کند.
- اجرای جامع Python پیش از به‌روزرسانی یک تست قدیمی: ۱۴۸۳ آزمون، یک شکست مربوط به انتظارِ منسوخ حداقل طول رمز (تست رمز ۵ کاراکتری را رد می‌خواست، ولی تصمیم مالک حداقل ۴ است). پس از اصلاح همان assertion در `tests/test_standalone_accounting_authorization_contract.py`، **۱۷ تست ماژول هویت موفق** (دو مورد expected failure). **کل مجموعهٔ ۱۴۸۳ تایی پس از این اصلاح دوباره اجرا نشده** و نباید به‌عنوان PASS کامل گزارش شود.
- آزمون Chromium مرتبط با تغییر DOM، حذف و جابه‌جایی مرحله توسط worker ثبت شده است؛ تأیید دستی در همهٔ viewportها انجام نشده است.

## حدود و موارد باز

- منوی کنونی معادل کل امکانات Trello نیست: **Copy list، Pin، Watch و Automation** هنوز پیاده نشده‌اند. منوی برد عمومی به‌جای آرشیو، توضیحِ علت نبود آرشیو همان نما را نشان می‌دهد.
- اثر منو و حذف مراحل در تمام حالت‌های mobile، keyboard Tab، زوم ۲۰۰٪، تم‌ها، کاربران کم‌مجوز، ستون با بیش از ۴۸ کارت و لمس/Drag هنوز end-to-end روی نصب نهایی تأیید نشده است.
- هیچ دادهٔ مالی واقعی و فایل کاربر برای ایجاد/حذف فهرست آزمایشی تغییر داده نشده است. تست isolated تضمین پذیرش نسخهٔ عملیاتی حسابداری نیست.
- ساخت EXE/Installer جدید، QA چنددستگاهی، تست نگهداری/بازیابی مالی، و تأیید انسانی روی پنجرهٔ اصلی گیت‌های پذیرش جداگانه دارند.
