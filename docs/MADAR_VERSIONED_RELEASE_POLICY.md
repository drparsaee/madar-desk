# مدار | قرارداد انتشار و به‌روزرسانی از نسخه ۱.۰.۱

**وضعیت:** مسیر ارتقای ۱.۰.۱ به ۱.۰.۲ پیاده‌سازی شده است. این سند، تأیید نصب بر تمام نسخه‌های ویندوز یا تأیید پذیرش تجاری نیست.

## اصول ثابت هر انتشار

1. نسخه‌های اجرایی داخل پوشه versions در مسیر LOCALAPPDATA/Programs/MadarDesk به‌صورت جانبی نصب می‌شوند. نسخه قبلی هنگام به‌روزرسانی بازنویسی نمی‌شود.
2. اطلاعات کاربر در APPDATA/MadarDesk باقی می‌ماند و هیچ فایل داده‌ای در فهرست فایل‌های مالک‌شده توسط Inno Setup قرار ندارد. حذف برنامه نباید این پوشه را پاک کند.
3. قبل از کپی نسخه جدید باید تمام فرایندهای Madar و سرویس MadarHost بسته باشند. برای داده موجود، snapshot مستقل در LOCALAPPDATA/MadarDesk-ReleaseBackups ایجاد و تعداد، اندازه و SHA256 محتواهای آن تأیید می‌شود. خطا = توقف نصب.
4. فعال‌سازی پس از کپی نسخه جدید و تطبیق هش فایل اجرایی انجام می‌شود. فایل current-version.txt با فایل موقت و جایگزینی اتمیک عوض می‌شود. previous-version.txt نسخه قبل را نگه می‌دارد.
5. بازگشت به نسخه قدیم فقط پس از کنترل سازگاری schema و با بسته‌بودن نویسنده‌ها مجاز است. بازیابی خودکار داده‌ها در همه شرایط هنوز اثبات نشده است.
6. WebView2 Runtime آفلاین x64 داخل همان فایل نصب قرار دارد و فقط در صورت نیاز اجرا می‌شود. مشتری برای استفاده از EXE نیازی به نصب جداگانه Python یا Node ندارد.

## محدوده سازگاری و امنیت

- هدف انتشار: Windows 10 x64 build 17763 یا جدیدتر و Windows 11 x64. Windows 7/8، x86 و ARM64 در این بسته پشتیبانی تأییدشده ندارند.
- فایل‌های تولیدشده هنوز امضای Authenticode معتبر ندارند. SmartScreen یا Smart App Control ممکن است هشدار بدهند یا مانع اجرا شوند. برای انتشار تجاری، امضای معتبر یک ناشر ثابت همراه با timestamp و ترجیحاً کانال Microsoft Store ضروری است. امضای معتبر هم حذف فوری همه هشدارها را تضمین نمی‌کند. غیرفعال‌کردن Defender یا خودامضایی راه‌حل انتشار نیست.
- شرکت سازنده Inno Setup برای استفاده تجاری درخواست خرید مجوز دارد. وضعیت مجوز محصول پیش از توزیع عمومی باید مشخص شود.
- آزمون روی Windows 10 و Windows 11 تازه، دستگاه فاقد WebView2، تنظیمات امنیتی سازمانی و بازیابی کامل داده جزو گیت‌های باز هستند.

### اصلاح آماده انتشار بعدی: محدودسازی HTTP شبکه

- در سورس پس از ۱.۰.۲، `LanService.start()` تنها برای bind با IP عددی loopback اجازه HTTP می‌دهد. bind روی `0.0.0.0` یا دیگر نشانی‌های شبکه بدون TLS، قبل از بازکردن سوکت رد می‌شود.
- `Bridge.lanHost()` به گواهی و کلید HTTPS نیاز دارد؛ کلاینت قبل از ارسال رمز/توکن، HTTP به IP غیر-loopback را رد می‌کند. تنظیم legacy ذخیره‌شده با HTTP خودکار راه نمی‌افتد و باید از پنل روی HTTPS پیکربندی شود.
- پیکربندی قدیمی به‌صورت خودکار به پروفایل جدید تبدیل یا حذف نمی‌شود. فایل‌های داده و کش آفلاین نباید برای رفع اتصال ناامن دست‌کاری شوند.
- این تغییر هنوز بخشی از بسته نصب‌شده ۱.۰.۲ نیست. تا ساخت و آزمون نسخه جدید و نصب امن آن، اصلاح کد به معنی اصلاح نسخه در حال اجرای مشتری نیست.
- برای LAN واقعی تهیه گواهی/کلید منحصر‌به‌فرد و راستی‌آزمایی SHA-256 pin نزد کلاینت لازم است. آزمون MITM شبکه فیزیکی و چرخه تعویض گواهی همچنان بازند.

## شواهد آزمون

نسخه ۱.۰.۲ با Inno Setup در محیط مصنوعی روی نسخه ۱.۰.۱ دارای دو پروژه، چهار کارت و یک پیوست نصب شد. فایل قدیم محفوظ، اشاره‌گر نسخه جدید، snapshot ZIP قابل خواندن، و محتوای فایل‌ها پیش و پس از ارتقا یکسان بود. ساخت EXE، اجرای رابط واقعی و شروع خالی برای کاربر جدید نیز آزموده شد.

این آزمون جایگزین تست بازگردانی داده واقعی، قطع ناگهانی برق، دو کامپیوتر یا حسابداری عملیاتی نیست. اطلاعات واقعی مالک برای این آزمایش‌ها تغییر داده نشده‌اند.

## مسیر بازتولید
