## Isolated upgrade and rollback QA

`scripts/qa_p0_v124_upgrade.py` uses only the fixed, owned
`.qa-inno-v124-p0-20261107` path and never runs the production setup.
It seeded a synthetic 1.0.23 installation, executed the **QA-only**
1.0.24 installer, then verified:

- Old 1.0.23 EXE hash unchanged, active/previous pointers 1.0.24/1.0.23.
- All three synthetic profile files preserved byte-for-byte.
- One pre-upgrade ZIP readable and its three file hashes matched.
- Implicit downgrade refused; explicit rollback with an incorrect SHA refused.
- Explicit rollback to 1.0.23, then verified forward activation to 1.0.24.
- The packaged **1.0.24 EXE** launched with isolated APPDATA and showed the
  real WebView2 task UI. The harness closed only its own subprocess tree.

Initial QA runner stopped after successful Inno install due to a Python
`utf8-sig` typo in the test harness, not a demonstrated installer failure.
The harness was corrected to `utf-8-sig` and resumed **without reinstalling
or overwriting** from the exact QA marker. Resumed process exit 0; receipt:
`release/Madar-Desk-1.0.24-P0-QA.acceptance.json`.
The synthetic QA folder was retained deliberately as evidence.

## Test results and remaining gates

- P0 candidate targeted Node: **15/15** passed; Python **42/42** passed.
- Web source after latest autosave fix: `npm.cmd run test:web` built and
  **44/44** passed, including browser, API, offline and role tests.
- Native legacy full test runner `py -3.12 -B tools/safe_test_runner.py`
  **did not pass**: 203 Python modules executed, 172 passed, 31 failed,
  21 test assertions failed and 124 errors. This runner stopped before its
  Node stage. Four representative failing suites were run on both immutable
  1.0.23 and native integration in equivalent isolated test profiles and
  failed identically: `test_purchase_intake`, `test_release_persistence`,
  `test_unified_bridge`, `test_provider_csv_bridge`. Their expectations
  reference removed/disabled integrated accounting contracts, whereas
  accounting now belongs in independent Taraz. **This limited baseline
  comparison does not classify all 31 failures as inherited.** The legacy
  test inventory needs explicit retirement/rerouting before a green
  release-wide suite can be claimed.
- Not tested: live user-profile migration, rollback with real users' data,
  multiple physical Windows PCs, Authenticode-signed publication, Windows 11
  clean VM, actual public GitHub Release or hosted web.

## Disposition

**Local P0 engineering/QA candidate assembled and synthetic
install/upgrade/rollback verified. Public release gate NOT APPROVED.**
Maintain immutable 1.0.23 installation; do not relabel 1.0.24 as a shipped
version or overwrite old manifests. Signing and full test-suite
classification remain explicit release blockers.
