## Verified and known limitations at base 6cc0454

1. **Correct host access denial:** `accounting_view(..., actor='qa-revoked', accounts=...)` raises `PermissionError` with revoked `financeView` and no editor write grant.
2. **Current authorized snapshot:** exact invoice and bill IDs open their detail cards; customer, account and journal IDs are searchable in the real React workspace. Account selection filters the account movement view. Customer search navigates to the persons page. The journal result navigates to the journal table with that ID, but does **not** uniquely highlight/focus it.
3. **Unsaved edits:** selecting a different invoice from Ctrl+K invokes a confirmation. Cancelling preserves the edited form, with no financial mutation; accepting opens the record.
4. **Role and company separation:** a viewer with explicit `financeView=true` may see their company's invoices and accounts, but cannot create or approve documents; search does not index an invoice belonging to a different synthetic company. The mobile UI has one compact primary navigation row at 390px, preserves a More menu and supports the advanced toggle; 1440px exposes the advanced Ribbon. This UI result does **not** itself establish host ACL security for real accounts.
5. **Critical, reproduced at base 6cc0454:** when a subsequent `standaloneAccountingRead` fails with `Accounting read access denied`, the workspace retains the old `snapshot`. Ctrl+K still offers the old invoice and its journal despite the host having revoked reading permission. The explicit revocation regression **fails** on base 6cc0454, as intended; source repair is outside this worker's ownership. The integration owner must clear cached financial views and callbacks on failed/denied read, then run the test against the repaired integration.
6. **Incomplete target deep links:** receipts/payments navigate to the settlement page and set transaction kind but do not select or focus the requested receipt/payment row. Journal search likewise navigates to the journal list without exact selection. Person search changes the party query but does not focus a unique person detail record. The tests verify route + row existence, **not** a falsely claimed exact selected-row deep link. A future, separate acceptance test should require a visible/focused exact target for all kinds.
7. **Customization key collision:** `StandaloneAccountingWorkspace` uses `snapshot.currentUser.username + '|' + view.companyWorkspaceLabel` as `preferenceKey` for local action-home layout. `standalone_accounting_desktop.py` derives `companyWorkspaceLabel` from `self.company_name`; this is a **display label**, not a stable company identifier. Two companies with the same label and username could share a personalization key. The pure `accounting_core` view does not include `companyWorkspaceLabel`, so the synthetic fixture has no persisted layout key. This is not a financial-ledger data collision.
8. **Old UX audit hang:** `scripts/madar_ux_completion_audit_20261103.cjs` used to unconditionally wait for `.sac-ribbon-tabs button` even though the app starts in *simple* mode, and it searched for the deleted inline searchbox. Updated audit startup branches on mobile 390/560 vs desktop 768/1440, selects advanced when visible, and uses the modal Ctrl+K combobox and More-menu invoice action. Other historic audit assertions still reflect an older interface (e.g. desktop Ribbon called a novice route, missing legacy quick buttons, and report data absent in the fixture); non-green audit results **must not** be classified as full UX failure or full UX success without reviewing individual checkpoints. This change corrects the hang, not all old acceptance definitions.

## Reproduction and acceptance gate

Run the new Chromium regression on the exact branch under review. The **revocation test must become green on the integrated repair commit**; do not suppress it, skip it or treat the old failing baseline as passed. Successful browser smoke on a synthetic fixture does not prove Windows installer behavior, real multi-company identity switching, persistence, screen reader usability, or WCAG conformance. No main push/release was performed in this review branch.
