# E2 MadarHost TLS metadata-only pilot (isolated, NOT RELEASED)

**Scope:** `mtr_lan_finance_adapter.py`, `lan.py` opt-in dispatch and
`tests/test_mtr_lan_finance_adapter.py`, using the separate E2
`mtr_host_request_store.py` SQLite backend. This is *not* an authenticated
Madar-to-Taraz transport or an official financial receipt.

## Activation and identity

- Default: `LanService.mtr_finance_adapter is None`; all `/api/mtr/v2/*`
  requests respond 404. No installer configuration or real host is modified.
- The trusted host Python process may explicitly call
  `service.mount_mtr_finance_pilot(store, org_id=trusted_org)` **after** the
  existing HTTPS listener starts. Mount is refused without a live TLS socket
  and requires a `HostRequestStore` at an explicitly chosen protected path.
  The browser cannot mount this API, set the DB path or select organization.
- Requests require the existing authenticated LAN bearer, revalidated against
  current `LanService.users`, session expiry, financeEdit/admin and current
  saved task's project grant while `service.lock` and `bridge._lock` are held.
  The server creates a typed `TrustedPrincipal` with a SHA-256 digest of the
  bearer as its session binding, never copying a client actor/role/org.
- There is **no** Taraz peer authentication or signing in this pilot. That
  boundary must be implemented separately before a receipt can be trusted.

## Deliberately narrow routes

All routes are `POST`, JSON-only, maximum **4096 request-body bytes**, on the
existing pinned HTTPS LAN connection. Raw duplicate JSON fields, nonfinite
numbers, extra properties and caller-chosen finance metadata are rejected.

| Route | Accepted properties | Server action |
|---|---|---|
| `/api/mtr/v2/prepare` | `requestId`, `taskId`, `prepareKey`, `manualAction: true` | Resolves current saved card and content revision; stores bounded schema-1 metadata with stable UUID and prepare key |
| `/api/mtr/v2/manual-send` | `requestId`, `taskId`, `sendKey`, `payloadSha256`, `baseRevision`, `manualAction: true` | Revalidates original card/payload/current revision and **records only the unsent manual authorization intent** |
| `/api/mtr/v2/status` | `requestId`, `taskId`, `baseRevision` | Returns scoped read-only host intent/receipt-state metadata; never queries Taraz itself |

The source-derived exact 52-bit positive integer revision hashes the complete
saved card. Changes to the saved card stop a stale *new authorization*; old
status can still be read by the original authorized session. No monetary
amount is accepted from the request. `createdUtc` is generated by the host,
and replay uses the original persisted metadata. Existing idempotency keys
must match the same actor, session, scope, revision and content.

`transportCalled=false` and `financialEventCreated=false` are explicit in
the store results. `receiptState=unknown` means **query the separately
authenticated Taraz authority first**, never infer `not_received` from
timeouts, and never automatically replay. There is intentionally no
`receipt-ingest` HTTP endpoint, ledger/invoice/party writer, outbound network
client, or background sender.

## Remaining operational blockers

1. A real Taraz peer process, provisioned/rotatable device/service identity,
   mutually authenticated transport, independently verified receipt contract,
   durable Taraz-side request registry and idempotent official ledger policy.
2. A centrally provisioned organization directory. The current LAN account
   registry has no verified multi-org membership; this pilot accepts only the
   trusted host's explicitly configured single organization.
3. Session-scoped records intentionally become inaccessible to a freshly
   logged-in bearer after host restart. Reviewed, scoped recovery and backup
   readback must precede any production activation. Local SQLite durability
   does not prove lossless physical power failure or multi-PC recovery.
4. UI integration of the new host endpoint, offline retry/reconciliation,
   Windows installed-host/two-PC tests, key compromise/revocation drills,
   G-01..08 and AC-05..13 acceptance, and release authorization.

```powershell
py -3.12 -B -m unittest -q tests.test_mtr_lan_finance_adapter
py -3.12 -B -m unittest -q tests.test_mtr_lan_finance_adapter tests.test_mtr_host_request_store tests.test_integration_api_v1 tests.test_integration_http_security

```

These commands use only `TemporaryDirectory` test fixtures, loopback TLS
with the existing **public test-only certificate**, and a disposable SQLite
DB. An all-green pilot does not mean the installed product has been tested.
