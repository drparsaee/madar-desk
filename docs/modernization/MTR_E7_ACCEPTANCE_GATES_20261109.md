## Practical blockers and conditions for accepting the gates

1. **Host-authenticated transport is the critical path.** The present shared `%LOCALAPPDATA%/Madar-Taraz-Bridge` folder gives filesystem observations with cooperative locks. A local path, a caller-supplied ACL boolean or an unsigned review marker cannot authenticate an organization, a finance user, a receipt or a posted document. E2 needs an explicit versioned request/response schema, service identity, authenticated TLS/peer binding, server-enforced tenant/role/field authorization, verified receipt identity and replay/query protocol. A client-supplied project grant must not be trusted as server authorization.
2. **Exactly-once finance requires Taraz-side authority.** `os.link` is an exclusive local file publication step, not a ledger transaction. A same-ID local retry and crash-safe metadata intent do not demonstrate exactly-once invoice/GL creation. Query-before-replay on authenticated status, durable first-send ID before dispatch, transactional idempotency key, monotonic official statuses and safe simultaneous requests must be tested against a Taraz finance integration contract. Unknown responses must remain `unknown`, never auto-resend or claim posting.
3. **Two physical environments are missing.** Synthetic Python subprocess tests on the same workstation share one filesystem and OS; they do not exercise two separate user profiles, physical LAN client/server, remote/TLS peer failure, key rotation, offline reconnection, cross-organization access or GUI/WebView2 performance. E7 requires a controlled Windows host and two clients, plus isolated remote/TLS scenario, with baseline checks that printers, file shares, LAN service and other users remain unaffected.
4. **Operational release gates remain separate.** Verify official Taraz catalog/data ownership, actor/timestamp audit, immutable history, explicit finance decisions and document reference provenance; isolate test identities/data; run conflict/IDOR/unknown-schema/aborted-transfer negative suites. Execute a reversible install/upgrade/backup/readback/rollback trial on disposable profiles and only then request independent deployment approval. No source review, synthetic test count, Vite build or Git commit replaces these controls.
