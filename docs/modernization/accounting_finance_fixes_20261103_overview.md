# Accounting finance fixes: code and side-effect inventory

The trusted desktop or LAN host passes `actor`, `accounts`, `now`, event command and expected revision to `StandaloneAccountingStore.command`. `accounting_core.apply_accounting_command` projects an event-sourced ledger, runs permission checks, applies commands, validates operational and party balances, hashes one new event and returns a new state. The host persists through SQLite CAS; the UI does not authorize posting. `accounting_view` returns an authenticated company-wide projection. `standalone_financial_report_host.attach_verified_reports` adds `ledger_reports` to that view, without writing to the database.

`accounting_operational_extensions.apply_extended` implements `fiscal.year.close`, stock receipt and stock issue as linked immutable journal entries. A purchase bill posts expense and purchase tax according to the existing accounting rules; a later untaxed stock receipt moves purchase expense to the inventory asset. A stock issue debits COGS and credits inventory, but issuance is currently a separate operation. No safe global tax recoverability or per-line allocation policy is stored in the current document model.

The standalone tax advisor `preflight_einvoice` is an offline **advisory** and sets both `readyForSubmission` and `submissionPermitted` false. It neither signs nor transmits to a tax system. `company.profile.set` exists behind administrator permission and has an audit trail. With optional fixed UTC offset minutes and explicit `postingCalendarMode="fixed-offset-no-dst"`, the company day can be derived from the host's trusted timestamp without relying on machine locale. Named timezones and seasonal DST are not accepted through this contract. Existing snapshots without the field retain their prior interpretation; frontend `standaloneToday()` must still be aligned by the integration owner.

Source files: `accounting_core.py`, `accounting_operational_extensions.py`, `accounting_reporting.py`, `standalone_accounting_tax_advisor.py`. Read-only callers include the standalone financial report host and direct reporting utilities. Focused synthetic tests live under `tests/test_accounting_reporting.py`, `tests/test_accounting_company_posting_offset.py`, and `tests/test_standalone_accounting_tax_advisor.py`.
