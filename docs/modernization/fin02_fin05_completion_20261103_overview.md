# FIN-02 / FIN-05 implementation overview

Source baseline: `6cc045446b37a23bb217cda566d785e73aed4c9e` on an isolated sibling worktree. No real accounting/profile files are read or written by tests.

`accounting_core._issue` posts purchase expense, discount, tax expense and payable in integer ledger units at bill issuance. The host persists a verified event through SQLite compare-and-swap. The read-only accounting view and `ledger_reports` validate double-entry and stock subledger against inventory asset 1300. `accounting_operational_extensions.apply_extended` handles warehouse events and their financial postings; `_take_fifo` consumes exact positive whole-unit layer values, and `inventory.reverse` posts an opposite journal without rewriting a previous financial event.

The new opt-in `inventory.receive` mode `per-line-exact` is administrator-only. It preserves previous `single-line-uniform` receipts and related old event replay. Operators enter the entire supplier bill discount allocation in line-index order, including zero shares on service lines. The code checks exact integer amounts, bounds against line gross, sum against posted bill discount, invoice linkage, system accounts 1300/5100/5200 where relevant, and a stable operator-provided evidence reference and reason. A different allocation on subsequent receipts of that bill is refused. These identifiers document an operator assertion; **they are not independently verified supplier documents**.

For each item, original purchase quantity minus returned quantity determines the current allocation interval. The receipt uses deterministic integer higher-cost-first FIFO units; residual one-unit rounding is distributed by index across warehouse receipts. New layers have an internal `@receipt:`-prefixed source label outside the legal bill/event ID alphabet, and their quantity/value is checked before reversal. This avoids accidentally reversing a different receipt on the same bill or SKU. No imaginary recoverable VAT, account asset or tax policy is added: `taxTreatment='expense'` retains posted expense account 5200.

`accounting_core._partial_return` uses each declared line's cumulative returned share to correct discount on subsequent purchase credit notes. Untaxed partial returns and taxed full-document returns are supported; taxed partial returns in the new exact-allocation mode are blocked because the source lacks per-line tax evidence. Existing stock movements must be reversed before return, and allocating a previously returned bill for the first time after a historical credit note is blocked because the old return may have used a different discount basis. Duplicate item IDs within one purchase bill, zero-cost FIFO units and unsupported tax recoverability also fail closed.
